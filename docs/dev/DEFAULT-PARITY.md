# Default 逻辑对齐（shadcn 只做视觉层）· 设计稿

> 状态：**已确认，执行中**。默认：选手端 + 管理端**全部主流程页面**均按 Default
> 的逻辑、子页面层级与交互重构；URL 先保留当前 shadcn 路径。
>
> 参考：
> - Default 前端：`frontends/default/`（逻辑、路由、页面层级、交互的唯一标准）
> - 视觉指南：[`docs/theme.md`](../../../docs/theme.md)
> - 历史问题：[`docs/frontend-bugs.md`](../../../docs/frontend-bugs.md)
> - 当前逐轮验收：`docs/qa/AUDIT-50.md`

## 1. 目标

把当前 shadcn 前端从“自建 IA + 自建工作流”改回 **Default 的 IA / 页面层级 / 交互逻辑**，
只保留 shadcn 的视觉与组件实现（Tailwind v4、shadcn/ui、Geist、亮暗主题、⌘K 等增强）。

一句话：**Default 决定“怎么走、看到什么、按钮做什么”；shadcn 决定“长什么样”。**

## 2. 范围（B）

### 选手端主流程

- Top / 总览落地页
- 赛事列表、Jeopardy 赛事工作区、AWD 驾驶舱、AWDP 工作台及各子页
- 题库、题集、GameBox / 训练场、实例、解题流水
- 公告、讨论、Writeup、武器库、个人资料

### 管理端主流程

- 控制台、赛事管理、题库、题集、GameBox、用户、角色、设置、计划任务、日志
- AWD / AWDP 运维

### 暂不纳入

OIDC Clients、Developer Apps、Docker、Database、Terminal、Authorized Apps。
这些页面继续保留现状，不阻塞主流程对齐；后续单独立项。

## 3. 不变量

1. **不把 shadcn 当前的自定义 IA 当标准**：`/` 总览、`/events` 工作区、`/training` 等路径可以继续存在，但页面内容、Tab、操作顺序按 Default。
2. **不改后端契约**；只消费现有 SDK / 真实接口，不用假数据补视觉。
3. **保留 shadcn 主题与组件**：不引入 Primer，不照搬 Default 的视觉样式。
4. **保留现有 URL**（先不做 `/service/*` 全量迁移）；页面内交互与 Default 对齐。后续如需 URL 完全一致，另做兼容重定向。
5. 破坏性操作、权限、状态、计分仍以真实 API 为准；视觉重做不得改变语义。

## 4. 页面层级与交互规则

### 4.1 应用外壳

- 侧栏分组、顺序、命名、折叠行为按 Default 的 service/admin 导航；
- 页面头部：标题、描述、主操作位置按 Default 对应页；
- 赛事详情、AWD/AWDP 工作区保留 Default 的“详情页隐藏/收敛侧栏”的层级感，而不是把所有内容塞进普通列表页。

### 4.2 列表与详情

- 列表页必须有 Default 的筛选栏、排序/搜索、批量选择、空态与错误态；
- **能用弹窗完成的编辑/查看，不再强制跳新页面**：例如题集列表的查看/编辑、增删题目；
- Default 本身是独立工作区的页面（赛事工作区、AWDP 训练 run）仍保留独立页面；
- 深链接仍要可用：直接打开详情 URL 时能回退到对应列表或渲染同内容 Dialog。

### 4.3 表单与危险操作

- 创建/编辑使用 Dialog / Sheet，沿用 Default 的字段顺序、校验与提交后行为；
- 删除、退出、重置、结束比赛等保留 Default 的确认层级与后果说明；
- 成功后按 Default 的失效范围刷新列表/详情，不整页刷新。

### 4.4 赛事工作区

- Jeopardy / AWD / AWDP 的 Tab 名称、顺序、可见条件按 Default；
- 积分榜、趋势、题目、实例、公告、Writeup、成员/战队等子页结构按 Default；
- AWD/AWDP 生命周期按钮的可用性、确认、状态刷新逻辑继续使用已核实的后端语义。

## 5. 分阶段实施

1. **Parity 审计**：逐页对照 Default 与当前 shadcn，产出差距矩阵（路由、布局、筛选、弹窗、动作、空态）。
2. **外壳 + 题集样板**：先做导航/头部/列表筛选 + 题集 Dialog（查看、编辑、增删题目），作为验收样板。
3. **选手端主流程**：赛事列表/工作区、题库/题集、GameBox/训练、实例/流水、社区/资料。
4. **管理端主流程**：控制台、赛事、题库/题集、GameBox、用户/角色、设置/任务/日志、AWD/AWDP 运维。
5. **回归与交付**：真实 API 全链路、320/390 移动端、i18n/theme/build、截图与问题台账更新。

每个阶段单独提交、单独验收；不一次性大爆炸重写。

## 6. 验收标准

- 与 Default 同页并排走查：入口、Tab、筛选、主操作、空态/错误态、危险操作确认一致；
- 列表交互优先弹窗/抽屉，不再出现无必要的路由跳转；
- 真实 API 下创建/编辑/删除/刷新后状态正确；
- 现有 shadcn 主题、亮暗、i18n、响应式不回退；
- 每阶段更新 `docs/frontend-bugs.md` 与验收记录。

## 7. 已确认的决策

1. URL 保留现有 shadcn 路径；只对齐页面结构、层级与交互。
2. 题集弹窗**两端都改**；不只题集，其他页面同样按 Default 的交互处理。
3. 所有主流程页面逐页对照 Default，不允许“这个页先自创一套”。
4. 详情 URL 仍可直达；列表不再强制跳详情，能弹窗完成的就在当前页完成。

## 8. 首个样板

先做「应用外壳 + 题集列表/弹窗」，但这不是最终范围；样板验收通过后立即按
§5 的顺序覆盖其余页面。
